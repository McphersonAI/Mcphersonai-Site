Authority stays with your systems.

SHADOW ONLY · AUTHORITY NONE · ENFORCEMENT OFF

Observa records and evaluates in SHADOW. It does not grant customer authorization or replace your approval controls. A WOULD_DENY result describes a counterfactual decision; it does not mean the action was blocked.

Metadata has a boundary. It still needs review.

The OpenClaw package sends runtime identity and roster information, heartbeat state, and action classification, executable names and argument digests for SHADOW evaluation. Its ordinary observation and evaluation contracts omit prompts, message bodies, command bodies, tool results and environment values. The n8n hook uses execution fields and excludes item data, node parameter values, credentials and workflow static data. Configured outcome checks are a separate path and can send selected business-rule facts in a source proof.

These are package-specific contracts, not a universal data-loss-prevention guarantee. Opaque identifiers can contain customer information. Review the fields and identifiers in your own authorized test scope before sending evidence. Do not use real regulated or confidential client data in a synthetic evaluation.

Separate system access from Observa identity.

Your workflow’s system credentials and customer authorization remain your responsibility. Observa pairing issues an installation credential for Hosted delivery; that credential is stored locally. The Local Node n8n path also requires a local loopback credential for communication between n8n and the observer.

The reviewed pairing implementations write credentials to owner-restricted local files and omit credential values from normal CLI output. This is not a claim of encryption at rest. Host administrators and the runtime’s process permissions remain part of your security boundary. Never send pairing codes or credentials in an application or support message.

An installation is not blanket tenant assurance.

Pairing binds an installation to the organization/workspace authorized through Hosted onboarding. Local Node checks the signed composition’s installation binding before composing components. These package checks do not establish a universal tenant-isolation guarantee across Hosted operations.

Customer configuration, host access and the Hosted agreement still need review for the intended deployment.

Missing evidence does not become success.

A completed action, a SHADOW decision and a system-of-record outcome are separate records. Incomplete evidence remains uncertain. OpenClaw local views report truncation and rejected-record warnings; a healthy connection is not proof that every action was captured.

UNCERTAIN remains uncertain. A matching fixture does not establish external qualification.

SHADOW does not mean zero technical impact.

Integration adds local work and, when paired, network exchanges. Evaluate runtime behavior, evidence delivery and failure conditions in an authorized staging environment. This site publishes no normalized performance number.

The OpenClaw release declares Node.js ≥22 and OpenClaw plugin API ≥2026.8.2. Local Node declares Node.js ≥22 and documents its n8n integration requirements. These declarations do not qualify every later version or topology.

Package facts and Hosted commitments are different.

  • OpenClaw’s released request path documents verified TLS to the endpoint bound at pairing. This does not establish encryption at rest or all Hosted infrastructure controls.
  • Local Node verifies a signed installation manifest and component hashes. Updates are operator-invoked; the package download alone does not start runtime collection.
  • OpenClaw runs inside its host gateway. Local Node runs an operator-started local process. Neither fact establishes a least-privilege guarantee for your host configuration.
  • Hosted handles account, credential-identity, evidence and security records. Operational backups and administrative access are part of that boundary. The Privacy notice describes these uses and deletion limits. No universal record-retention period, backup-erasure deadline, hosting-region promise or incident-notification deadline is offered here.

Stop observation and revoke delivery deliberately.

OpenClaw v0.7.4

observa disable stops plugin background Hosted traffic. Explicit access, pairing and revocation commands have separate semantics. observa unpair requests revocation; uninstalling alone does not revoke the credential.

Local Node 0.1.7

observa stop stops the local observer. observa unpair handles Hosted delivery revocation and local pairing state. observa uninstall --yes is not a substitute for revocation.
