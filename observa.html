Your agent says the job finished. Observa checks what actually happened.

Governance Analysis

What policy would have decided, while staying in SHADOW.

Available now in Hosted Observa for evaluated activity. A dedicated walkthrough of these states is in production; until then, here is exactly what the words mean.

  • WOULD_ALLOWAn enforcing policy would have permitted this action.
  • WOULD_DENYIt would have refused — and the action still ran, because nothing is enforced.
  • WOULD_REQUIRE_APPROVALIt would have held this for a human. Nothing was held.

Counterfactual by construction. Not every runtime action receives a decision; activity never becomes a decision on its own, and unevaluated activity stays visible as UNEVALUATED.

The conceptual model

Identity, capability, authority, execution, reality.

01

Discover

Identify the agents, tools, and capabilities operating in the connected environment.

02

Map

Create reviewable mappings between capabilities and governed meaning. A mapping proposal is not approval, activation, or authority; a person reviews and classifies it.

03

Observe

Capture structured execution evidence without taking production control.

04

Govern

Evaluate activity against defined governance boundaries and keep the results reviewable.

05

Verify

For supported workflows and authoritative systems, independently determine whether the intended state actually exists.

The key distinction

Runtime completion is not the same thing as verified.

Agent or runtime

“Task completed.”

Observa

“Did the authoritative system actually reach the intended state?”

Independent verification applies where an appropriate verification contract or profile exists for the workflow and the authoritative system. Observa does not claim that every arbitrary workflow can automatically be verified.

Verification boundary

The result should never outrun the evidence.

If authoritative readback confirms the intended state, the outcome is verified. If it disagrees, the mismatch stays visible. If evidence is unavailable or uncertain, the outcome remains nonverified. Uncertainty is never silently turned into success.

What verification can do

  • Compare supported workflow outcomes with authoritative system state
  • Mark an outcome verified only when readback confirms the intended state
  • Surface mismatches between what was claimed and what exists
  • Keep unverified and uncertain outcomes clearly labeled

What Observa does not assume

  • That a successful runtime response proves the intended downstream state exists
  • That every tool, system, or workflow has authoritative readback
  • That missing evidence means no action occurred
  • That a readable report is a compliance or safety certification
