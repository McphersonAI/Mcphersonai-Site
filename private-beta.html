What happens

Self-service request. Human-reviewed access.

You start the request yourself from the command line. A person still reviews every one, so the beta stays small and the feedback stays real — and founder-assisted onboarding remains available throughout.

Install the Local Node CLI

npm install -g @mcpherson-ai/observa-local-node

Request access

observa request-access --api-url https://governance-plane-observa.tailb473db.ts.net

Check where you stand, any time

observa request-status

Requires Node.js 22 or newer. Installing the package activates nothing: it has zero dependencies, runs no install scripts, and contacts nothing until you explicitly request access.

What SHADOW mode means

Observa watches and checks. It does not take the wheel.

In this beta, Observa observes, evaluates, maps, and verifies without taking control of production actions. Your systems keep doing exactly what they did before.

  • Supported discovery and mapping for approved n8n and OpenClaw workflows

  • Shadow policy evaluation with visible review state

Not included or authorized

  • No public self-service signup or anonymous connected dashboard

Private beta FAQ

The important boundaries, in plain language.

Does applying give me dashboard access?

No. observa request-access submits a request; it does not create connected access. A verified email moves the request to review, and a person decides. Founder-assisted onboarding is still available once you are approved.

Will the beta stop or approve agent actions?

No. Authority is NONE and enforcement is OFF. The beta observes supported activity, maps capabilities for human review, captures governance evidence, and independently verifies supported outcomes. It does not control production actions.

Is there a public signup or paid plan?

No. There is no public self-service account flow, billing, payment processing, or enforcement credit in this beta. Access is requested through this page and approved manually.

Does Observa verify every workflow outcome?

No. Independent verification applies to supported workflows where an appropriate verification contract or profile exists for the authoritative system. A successful runtime response is not treated as proof of the downstream state, and when evidence is unavailable or uncertain the outcome stays nonverified.

What do I need to bring?

One real, bounded n8n or OpenClaw workflow that you can discuss without sharing secrets or customer content. Version, hosting, and rollback readiness are confirmed together during onboarding.

Does the beta certify compliance or prove every outcome?

No. Coverage depends on supported integrations, mappings, evidence, and environment context. Unknown, incomplete, conflicting, or stale evidence remains unknown and must not be presented as proof.
