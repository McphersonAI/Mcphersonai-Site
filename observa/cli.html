CLI reference

Two packages. Two command sets.

Both packages use the executable name observa. Confirm the version and runtime before using a command. The examples below were checked against the public OpenClaw v0.7.4 and Local Node 0.1.7 artifacts.

Identify your package first.

observa --version
observa --help

Local Node prints observa-cli 0.1.7. OpenClaw prints Observa 0.7.4. Do not use the Local Node command as a substitute for a missing OpenClaw launcher.

Local Node 0.1.7.

observa status
observa inspect-workflow --file ./workflow.json
observa activity
observa decisions
observa agents
observa agent <id>
observa diagnose

Status and inspection are local. Workflow inspection reads structure only. Activity and decisions read available local evidence; they do not synthesize missing execution or policy results. Diagnose checks installation integrity and configured state. It is not an end-to-end delivery or business-outcome check.

Install and activate after access approval

observa pair --base-url "$OBSERVA_HOSTED_URL" --code-stdin
observa install
observa n8n-setup
observa start

Configure the local n8n loopback credential before n8n-setup, then load the generated environment into n8n and restart it. See Getting Started. A signed manifest and verified component hashes are required for installation.

Upgrade, stop and remove

observa update --manifest <newer-signed-manifest.json>
observa rollback
observa stop
observa unpair
observa uninstall --yes

A package upgrade and a signed composition update are different operations. Keep the running service, copied hook and loaded n8n hook at the same release. Use the upgrade checks. Unpair handles Hosted revocation; uninstall alone does not revoke. --purge-config additionally removes local configuration, so use it only when that is intended.

OpenClaw v0.7.4.

observa status
observa agents
observa agent <id>
observa activity --limit 20
observa decisions --limit 20

These local views do not contact Hosted. Status does not prove that the gateway is loaded or currently connected. Activity reads completion receipts; decision-only evidence is not activity. The inspected history is bounded and warnings remain significant.

Pair and check Hosted

observa pair --api-url "$OBSERVA_HOSTED_URL"
observa hosted-health
observa identify

Pair uses hidden terminal input or --code-file <owner-only-file>. It does not use Local Node’s --base-url flag. hosted-health contacts Hosted to inspect reachability and binding; identify can confirm the roster. Neither creates workflow activity.

Observation controls

observa disable
observa killswitch on
observa lock on
observa unpair
observa uninstall --yes

Disable, kill switch and lock stop Observa’s background Hosted traffic and its health/identify commands. Explicit access, pairing and unpairing follow separate paths. These controls stop observation, not the customer’s agents. Confirm revocation before uninstalling; uninstall is not revocation.

Shared access commands; distinct pairing flags.

For Hosted commands, set OBSERVA_HOSTED_URL to the HTTPS endpoint supplied for your evaluation. The variable below is a placeholder for that approved endpoint, not a public service address. If you do not have one, ask support for the evaluation endpoint. The CLI still performs email verification and access review; email to support does not grant access.

observa request-access --api-url "$OBSERVA_HOSTED_URL"
observa request-status

Follow the hidden email-code prompt and human review. Request credentials are separate from the later installation credential. Do not paste pairing or verification codes as command-line arguments.
