Access & pairing

A request is not a paired installation.

Email verification, access review, an invitation and pairing are distinct steps. Downloading a package or applying as a Founding Builder does not complete technical onboarding.

Request access through the CLI.

For Hosted commands, set OBSERVA_HOSTED_URL to the HTTPS endpoint supplied for your evaluation. The variable below is a placeholder for that approved endpoint, not a public service address. If you do not have one, ask support for the evaluation endpoint. The CLI still performs email verification and access review; email to support does not grant access.

observa request-access --api-url "$OBSERVA_HOSTED_URL"
observa request-status

Review the requested metadata, confirm the request and complete email verification. Check the saved request’s state with request-status. Approval remains human-reviewed. Retrying does not create an approved account.

Redeem the invitation, then create a pairing code.

After approval, use the invitation sent to your verified email, sign in and review the evaluation documents. Create a pairing code for the intended installation in Hosted. Access approval does not itself issue an installation credential or grant commercial deployment rights.

Keep the code private. The command-line request receipt is also private; do not send it to support. If invitation delivery needs retrying, use the current CLI’s request-access --resend flow.

Pair the intended runtime.

Local Node 0.1.7

observa pair --base-url "$OBSERVA_HOSTED_URL" --code-stdin
Reads the pairing code from standard input; use Ctrl-D to finish on Unix-like terminals. An owner-only file is supported via --code-file. Then observa install retrieves and verifies the manifest approved for this installation.

OpenClaw v0.7.4

observa pair --api-url "$OBSERVA_HOSTED_URL"
Reads the code at a hidden terminal prompt unless --code-file is supplied. Uses managed plugin installation, not the Local Node signed-composition installer.

Existing pairing and revocation.

Inspect the selected runtime/profile before changing pairing. OpenClaw’s --replace-existing is an explicit credential-replacement option; it is not a Local Node flag. Read observa pair --help for the installed OpenClaw version before replacing a credential.

Local Node can retain installation identity after unpair; the no-flag observa pair recovery path uses that existing identity. Do not treat it as a first-time pairing command. For either package, inspect command results: local uninstallation is not proof of Hosted revocation.
